# Neymi v1.3 开发说明

**更新日期：2026-10-25**
**用途：** 将当前产品目标、UI/UX、架构边界、开发顺序和代码验证状态汇总为一份入口文档。它反映仓库当前状态，不代表已经部署或通过真实服务验收。细节以文末链接的 PRD、UX、架构和验收文档为准。

## 产品目标

Neymi 帮用户为一场具体交流准备个人介绍。用户先免注册创建、预览和分享基础数字名片，再自愿使用 AI 整理本人事实、研究一位接收人，并审阅针对这次交流的表达方案。产品衡量表达是否清楚、材料是否真实和交流是否有帮助，不承诺对方反应或会面转化。

交付顺序是 **A 单人定制 → B 活动准备 → C 一个正式聊天渠道**。基础名片、查看、保存和回赠不要求注册。AI 个性化是拟收费方向，高级模板/动效是另一条增值方向；账号、订阅、支付和权益恢复目前不在 v1.3 实施范围，价格及会员功能仍待价值与成本验证后另立需求。

## 用户流程与界面要求

1. **免注册创建名片：** 从展示名称开始，公司、角色、模块和联系方式均可选；编辑时实时预览。提供六款免费风格：松林、素纸、海岸、陶土、夜航、紫藤。选择无需注册，并应沿用到分享预览、公开卡片和 PNG。
2. **联系方式：** 邮箱、电话、微信、WhatsApp 等敏感值通过独立本地表单保存。选择加密保存时才设置本地口令；AI 不读取联系方式。导出或公开前逐项确认，未选字段不得进入分享对象。
3. **AI 助手：** 逐次展示实际发送内容并征得云端处理同意；只发送本次获批文字和用户选择的已确认事实，不自动重传历史或完整资料。AI 提取的本人事实先作为候选，必须由用户编辑/确认后才在本地保存。
4. **单人准备：** 用户提供接收人的文字或公开链接及交流场景。研究需区分事实、用户提供信息、推断和未知，记录来源；身份不确定时先确认。表达策略说明本人材料与接收人依据，用户审阅后才在本地合成名片。
5. **分享与接收：** 导出文件、图片、vCard 或发布公开快照前显示最终字段。公开链接可被转发，默认 30 天到期并可撤下；撤下不能收回已下载副本或第三方缓存。接收人免注册查看、保存和回赠。

视觉基线为 5:3 横向名片、可变内容模块、详情展开、手机与桌面响应式，以及 reduced-motion 和键盘可用性。样式选择不决定名片模块数量或布局。当前实现里的 `keys` 动效只影响卡片标记闪动；旧版“琴键般浮动窗口”没有进入当前已实现界面。当前也没有统一的应用内返回按钮，且没有一键复制整张名片信息；现有复制操作用于交接链接或撤回密钥，名片本身可通过文件/vCard/PNG分享。

## v1.2 到 v1.3 的设计变化

你的判断基本正确：**v1.3 没有完整承接 v1.2 的名片视觉与交互规格。** v1.2 对卡片写得更具体：左上身份区、大小不等的透明浮动模块、点开后显示详情、每项旁边的复制图标、详情页返回箭头，以及 Floating Glass / Piano Keys / Orbit Reveal 三种动效；它也区分了分享封面与完整动态卡片。v1.3 保留了 5:3、可变模块、详情展开、三种动效名称、无障碍和响应式要求，但没有定义这些模块的具体样式/状态、复制与返回交互，也没有首页和各网页页面的完整视觉布局、色彩/字体/间距系统或页面原型。**这是规格细节的缺口，不代表旧设计已在当前产品实现。**

同时要区分：v1.2 文件自述是 Pilot 规格，并非完整可点击的 v1.2 原型；仓库保留的网页原型和图片标记为 v1.1。因此“v1.2 视觉要求比 v1.3 完整”成立，但“v1.2 已有全站最终设计稿”不成立。商业部分也有明确变化：v1.2 有 Signature Member、付费 Sleeve 和 T14 支付/邀请凭证任务；v1.3 将会员、支付和高级卡套移到 `P-LATER`，当前没有用户等级或付费设计。

## AI、隐私与技术边界

- 完整本人资料、私有标签和敏感联系方式保存在当前浏览器；本地加密保险库不等于账号或跨设备同步。
- AI/搜索服务只接收用户明确批准的最小上下文。服务器不能读取本地保险库，也不能因 AI 同意而自动获得最终分享权限。
- 用户确认的分享字段生成新的白名单投影；分享投影、研究任务和本人本地资料彼此分开。
- AI 不得编造本人业绩、对方兴趣或成功概率。研究缺证据时应明确表示未知或停止断言。模型输出须经 schema 和引用关系校验，人工评测仍是上线要求。
- 技术结构为 TypeScript/Next.js Web/PWA；本地 IndexedDB 与加密 vault；同源匿名 API；DeepSeek LLM、Tavily Search 适配器；公开快照使用独立存储。无密钥时必须明确报未配置，不能将 fixture 或规则后备描述成实时 AI/真实搜索。
- DeepSeek/Tavily 的供应商数据地区、留存、费用仍需核验。正式部署还需 HTTPS、稳定会话与发布密钥、持久存储、定时清理、备份恢复验证和真机测试。

## 本地配置与运行

项目目录：`E:\ChatGPT\neymi cybercard\Neymi_v1.2\Neymi_Dev_Package_v1.2`

在项目根目录创建 `.env.local`，只在服务端填写密钥，不要把密钥提交到 Git 或发送到聊天：

```dotenv
NEYMI_DEEPSEEK_API_KEY=
NEYMI_DEEPSEEK_MODEL=deepseek-flash
NEYMI_TAVILY_API_KEY=
NEYMI_SESSION_SECRET=
NEYMI_PUBLICATION_SECRET=
NEYMI_CLEANUP_SECRET=
NEYMI_SQLITE_PATH=./.data/neymi.sqlite
```

本地开发命令：`npm install`、`npm run dev`。常规验证：`npm run typecheck`、`npm run lint`、`npm test`、`npm run test:e2e`、`npm run build`。如果旧的 Next 开发进程仍占用 3000 或 `.next` 锁，需先在启动该进程的终端停止它，再启动新版本。
