# Neymi 账户、注册登录与付费权益设计

日期：2026-10-26。状态：产品设计草案，待用户确认；未实现、未开通收费。本文的套餐、额度与价格为设计建议，不代表用户已批准或已验证商业效果。

## 1. 依据与阶段澄清

依据现行 PRD、架构隐私文档、2026-10-26 基础名片与全局助手设计、同日实施计划 Task 7，以及 v1.2 历史 Signature Member / Identity Sleeve 方向。

现行约束：游客可免费制作、查看、保存、导出、回赠基础名片；注册开放更多模块；AI 个性化和批量活动准备是核心付费价值，高级外观为独立增值；完整资料与敏感保险库仍保存在本地。登录不得自动上传保险库，到期不得删除旧内容或阻断导出。

两条阶段编号不能混用：旧 v1.3 路线 C 是正式聊天渠道；2026-10-26 新计划第三阶段/Task 7 是账号与商业权益设计。旧 `phase-c-report.md` 不构成账号、支付完成证据。商业线后续使用 COM 编号。

当前代码仅有签名匿名会话、模块目录预览及本地资料，不具备真实账户、付费身份或服务端商业额度。本文新增设计不将现有代码标记为已完成。

## 2. 方案比较与推荐

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 仅按次购买 | 适合偶尔参加活动的人，成本容易对应 | 每次准备都有购买阻力，外观会员价值难表达 |
| 一个按月会员 | 权益易理解，身份/续费/额度链路最短 | 偶发用户可能不愿连续订阅 |
| 月会员加次数包 | 同时覆盖高频与偶发用户 | 要处理两种余额、有效期、退款及消费顺序 |

用户已确认同时面向大陆与海外。推荐一个 Pro 等级，首发两地均购买 30 天会员、到期手动续购；自动月续费作为后续独立开关，额度包暂缓。这样不依赖各支付方式均具备自动扣款资格。无需首发团队版、多个会员等级、年付、自动充值或终身无限 AI。该选择是本次设计建议，尚待用户确认。

## 4. 注册与登录

采用统一“登录 / 免费注册”入口：Google 继续、Apple 继续、邮箱验证码。大陆入口优先邮箱和 Apple，海外入口优先 Google/Apple，邮箱始终可选；区域可手动切换，不仅依赖 IP 判断。中英文覆盖登录、权益、付款与错误提示。首次完成身份验证创建免费账户，后续同一身份直接登录；首次建号明确展示服务条款、隐私说明及同意动作，营销订阅单独可选且默认关闭。

首版推荐邮箱验证码而非新增网站密码，减少密码恢复和用户混淆；邮箱验证码与本地保险库口令是两套用途。Google/Apple 是授权登录；输入 Gmail/iCloud 地址收验证码也是邮箱登录，不等于授予 Google/Apple 授权。

建议 Supabase Auth 托管三种身份方式，应用用稳定的用户 UUID 作为归属与账本主键。登录邮箱是账户信息，不自动填入名片、不发给 AI、不自动公开。只请求登录必需范围，不请求通讯录、邮件或云盘访问。

Google/Apple 身份是否归于同一账户由受信任身份服务的已验证规则处理，应用不得自行按邮箱字符串合并账户。Apple 隐藏邮箱可能与 Google 邮箱不同；账户中心提供“关联另一种登录方式”，需当前登录及新身份验证。已有独立账户的合并首版不自动处理，明确提示联系支持，不能丢失订单或把额度发放两次。解绑后必须至少保留一种已验证可用的登录方式。

邮箱登录建议验证码有效 10 分钟、重发间隔 60 秒，并限制尝试次数和发送频率；以供应商支持配置为实现前核对项。发送提示不泄露邮箱是否注册；验证码一次使用，失败不生成登录态。正式发送需配置并验证邮件域名与投递。

OAuth 返回只允许配置过的同源目的地，采用供应商推荐的 PKCE/回调校验。服务端验证会话后才读取账户权益。取消/失败返回发起位置，不清空本地名片。手机内置浏览器若不能完成授权，提示用系统浏览器继续，并说明原浏览器资料位置；邮箱验证码保留为另一入口。

## 5. 页面与关键流程

首页右上“登录 / 免费注册”；登录后为账户入口和会员状态。游客完成第一张卡后可轻提示注册权益，不弹窗阻断制作。

点击注册模块 → 展示真实示例和免费注册说明 → 登录 → 回到原模块，保留未提交输入；点击 Pro 功能 → 展示本次所需权益/额度 → 价格页 → 登录（若需要）→ 支付 → 服务端确认 → 回原任务。不得因支付成功自动调用 AI、上传资料或发卡，仍需用户确认本次操作。

建议页面：`/auth` 身份验证；`/account` 登录方式、会话、账户删除入口；`/pricing` 三层对比与一个 Pro 购买按钮；`/account/billing` 订单、当前周期、到期日、手动续购和额度明细（未来自动续费上线后才增加下次收费和取消续费）；`/account/data` 本地备份/恢复与资料所在设备说明。URL 是拟新增设计，不是已有路由。

支付返回页显示“正在确认付款”并查询服务端状态；取消显示未开通；确认后显示实际套餐与期限。不把浏览器回跳、查询参数或成功截图当成到账证据。

账户中心分别显示“账号已登录”“此设备资料”“会员有效期”；换设备登录可恢复权益，资料区为空时说明需要从原设备导出加密备份后导入，避免用户误以为资料丢失。

## 6. 本地资料接续、退出与删除

首次登录若检测到游客资料，展示“将此浏览器资料用于当前账户”的本地归属选择。仅写入本地 workspace 归属，不上传资料；取消时保留游客空间，不重复创建或覆盖资料。导入与迁移须事务化、可重试，迁移失败保留原数据。

按 guest 或稳定 userId 隔离本地工作空间。切换账户清空当前助手会话和内存明文，锁定原保险库，不向另一账户展示原账户资料。退出默认保留已锁定的本地空间，并提供单独的“清除此设备资料”动作及备份提示。非敏感本地资料当前并非全量加密；界面隔离不宣称能抵御同设备开发者工具读取。

登录不自动接管原匿名云端任务或公开链接管理权。原匿名任务继续按原 owner 与 TTL 处理；原公开快照保留既有撤下凭证。后续如增加“纳入账户管理”，必须验证原凭证并显式确认，不能依据名片邮箱认领。

删除账号需重新验证身份，展示未到期权益和公开卡片处理选项；若未来存在自动续费，先完成停止续费，避免删除后继续扣费。失败时保持可恢复的删除申请状态。账户删除不默认为删除全部本地资料或自动撤下匿名旧链接；应让用户明确选择并说明无法撤回第三方副本。付款记录保留规则由商户地区政策确定后写入正式隐私/退款说明。

删除前若此设备有账户资料，必须选择迁回游客空间、导出备份或明确删除，完成后才最终删除身份；已有游客空间时不静默覆盖，提示先导出备份或显式合并。其他设备离线资料无法远程迁移：提供凭本地保险库口令解锁并导出旧空间的恢复入口，不要求已删除账号再次登录；恢复只作用于当前设备，不获得云端权限。同邮箱重新注册不得自动认领旧 userId 或旧订单。

## 7. AI 额度如何计费

“1 人次”定义为一个获批输入版本下，针对一个接收人的研究、策略和可用名片方案完整交付；继续打开、手工编辑、重新导出已有结果不扣。更换接收人、目标或资料后主动重做，展示将再消耗 1 人次，确认后执行。

找亮点按一个成功回复扣 1 次，不与“人次”混用；每次输入、输出、搜索深度及供应商重试均有服务端成本上限。套餐额度是建议，不能在真实成本测量前承诺不限量。

请求开始在数据库事务内预占余额，任务成功提交时结算；无有效结果、超时或失败释放预占。重复请求、网络重试、刷新、重复回调不能重复扣除。同一幂等键且输入散列相同返回原任务；同键不同输入拒绝。每个预占有过期和对账机制，进程崩溃后不永久占用余额。

计费完成点为服务端已生成、通过结构/证据边界校验并持久保存的可取回策略与非敏感名片方案，不等待用户批准、应用或分享；结果质量不足以形成方案时按失败释放。用户主动不采用有效方案不会退回已消耗人次，发起前说明此规则。研究存储与计费库之间不假定跨库事务：先记录可恢复的结果和待结算事件，再以 reservationId 幂等结算；结算暂失败时任务为“确认额度中”，后台重试结算，不重跑供应商。成功结算但响应丢失时返回原结果。清理过期预占前须核对已准备结果，避免已成功却先释放；任务/结果沿用现有 24 小时 TTL，未能在 TTL 内解决的结算故障按失败释放或记一次补偿退款，并提供脱敏错误。此处退款指额度补偿，不自动发起现金退款。

活动对每人独立预占/结算，2 人成功 1 人失败仅扣 2 人次。名单提取与活动概览计入活动服务成本，不另扣人次；只对 Pro 开放且设置每天新分析上限（初始建议 5 次），防止零人次调用无限消耗。取消批次时已交付结果计费，未开始/未交付项释放；结算与取消并发以事务终态为准。

试用额度绑定用户，耗完不按月刷新。首发每次购买产生一个 30 天权益周期，自到账确认时开始；会员未到期不允许重复购买或提前叠加周期，避免双币种重复购买和权益冲突。到期后可手动购买新周期。未来自动续费按支付方计费周期发放，不按自然月。剩余周期额度不结转；试用余额在开通 Pro 时冻结，降回免费后恢复剩余，防止叠加规则不清。原周期已预占任务在周期结束后最多 15 分钟内完成并归属原周期，不占用新周期额度。

## 8. 定价、支付与到期

推荐先测试单一 Pro：大陆 ¥59/30 天，海外 US$9/30 天，权益相同，均手动续购。这是价值/成本假设，不是已批准售价，不是供应商报价。服务端分别管理人民币、美元商品价格，不由客户端按汇率转换；结账前清楚展示币种、应付总额及适用税费。首版不年付、不自动加购、不默认开通试用后扣费。登录 Apple 与 Apple Pay 是两项能力，不相互承诺。

价格可行性用实测评估：每名付费用户净收入减去 AI、搜索、邮件、托管、支付与退款相关成本；同时测满额用户成本，不能只用平均轻度用户成本推算。若上限成本不可承受，在收费上线前调整价格或额度并重新确认。

双市场建议先核验一个可同时支持海外银行卡和大陆钱包的获准收款服务，优先评估 Stripe Checkout 的一次性购买能力；目标用户在海外不代表商户已能开户，也不保证钱包资格或币种已获批。Stripe 官方资料说明微信支付不支持循环扣款，支付宝循环扣款需审批，因此首发使用 30 天一次性购买。若主体不能使用该方案，应核验其他获准服务或大陆商户通道，不能绕过准入条件。双市场上线必须分别通过大陆邮件/授权/付款和海外付款实测；未通过的一侧仅免费开放，不假称两地均已收费上线。

支付商品/金额/币种均由服务端白名单决定，客户端不提交任意价格。经签名校验的付款事件触发权益更新；事件 ID 幂等，乱序事件需核对支付方最新状态，并定期对账。订单、退款、订阅、权益账本分开记录，退款事件不能误撤另一周期权益。

首发规则：一次性付款确认后生效，每笔成功订单只发放一次周期额度，界面显示“30 天会员，不自动续费”。服务端创建结账会话时对同一账户加锁，重复点击复用未结束会话；跨渠道并发到账只激活一个周期，额外款项进入待退款队列并通知用户，不暗中叠加权益。到期停止新增付费任务，可继续读取、修改和导出旧内容，重新购买不重复发试用。

未来自动续费规则（首版不实现）：每次续费到账只发放一次新周期；用户取消后保留至 paidThrough；续费失败不延长已付期限。上线此模式前另行验收授权扣款、账单门户与取消流程，不把一次性购买客户自动转成订阅。

支付失败/未完成/支付回调延迟不显示成功；额度不足不自动收费。退款申请在账单页可见，首版可由人工通过支付方处理；到账确认后按被退款账单回收对应未使用额度及有效期，不删已生成资料。部分退款需要明确的对应权益调整记录，不做隐式比例猜测。具体退款窗口与法定要求须按销售地区另行确认，未确认前不开真实收费。

会员到期后停止新选 Pro 外观及新建付费任务，已保存和已发布卡片的已有外观继续可读、导出；公开快照仍按原发布到期规则运行。用户数据不成为续费筹码。

## 9. 服务端边界与数据设计

建议 Supabase Auth 管身份，Postgres 管账户/权益/计量/订单；当前研究与公开快照存储不因此全量迁库。只有实时 AI、支付和公开服务等服务器资源才能可靠强制计量；本地离线模块限制只是产品体验，不能宣传为不可绕过的付费保护。

首版最小新增数据：account(userId,status)、billingCustomer(userId,providerCustomerId)、order(userId,providerPaymentId,productId,currency,amount,status)、refund(orderId,providerRefundId,amount,status,entitlementAdjustment)、entitlementPeriod(userId,sourceOrderId,startsAt,endsAt,limits)、usageReservation(userId,jobId,inputDigest,kind,period,status,expiresAt)、usageLedger(reservationId,delta,reason)、paymentEvent(provider,eventId,processedAt)。订单一对一产生已付权益周期，退款独立审计；subscription(providerId,status,paidThrough,priceId) 留到 COM-05。外部 ID 唯一约束，账本审计可追溯，客户端无权写额度或身份归属。

账户邮箱由 Auth 管理；业务表不重复保存完整身份资料。账本只保留计费必需标识/计数，不记录接收人姓名、对话、名片正文或保险库内容。服务端密钥不进入客户端包。个人订单及权益只允许本人读取；管理端需要单独权限，不能靠前端隐藏。

拟新增接口职责：读取自身账号/权益/额度；创建受控结账会话；进入本人账单管理；验证并处理支付回调；预占/结算服务端任务额度。具体路由和 SDK 版本由实施计划结合当前 Next.js 文档决定；现有匿名 cookie 不能直接当登录身份。

## 10. 分批交付与验收
