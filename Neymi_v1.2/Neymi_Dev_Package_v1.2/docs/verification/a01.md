# A01 — 工程与数据边界验证

2026-10-24。开发分支 `codex/phase-a-foundation`。

## 范围

- 搭建 Next.js 16.4.3 / React 19.3.1 / TypeScript 5.9.3 / Zod 4.6.7 工程；锁定 npm 依赖，提供本地可启动的开发预览。
- 实现 v1.3 领域类型及严格运行时 schema；手工名片无需 AI 策略，AI Recipe 要求策略 ID；接收人可无活动 ID。
- 对 AI 文案中的常见电话、邮件、街道地址模式进行拒绝，对未知字段、证据跨人引用、未批准模块、失效授权进行拒绝。此模式检查不能代替后续 A05 的输出审查和云端传输控制。
- `ProfileItem.valueKind` 使电话、邮件、地址在重命名显示标签后仍需按敏感字段分类。完整加密保险库属于 A02，尚未实现。

- RED：48 项 Vitest 中 41 项按预期失败，7 项通过；失败来自临时宽松 schema 的实际行为。
- GREEN：`npm run test -- --reporter=dot`，48/48 通过。
- `npm run typecheck`、`npm run lint`、`npm run build` 均通过。生产构建首次在受限沙箱内创建 `.next` 时遇到 EPERM；使用正常文件系统权限重跑通过。
